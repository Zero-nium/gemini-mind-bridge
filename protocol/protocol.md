# Mind Bridge Protocol Specification (v0.1.0)

This document specifies the transport protocol and security controls for communication between the Mind Bridge Chrome Extension and the macOS Native Messaging Host (`com.mind.bridge`).

---

## 1. Protocol Envelope (JSON)

Communication occurs over Standard Input/Output (`stdin`/`stdout`) framed with a 4-byte little-endian integer prefix indicating message length.

### 1.1 Request Envelope (`ask_mind`)

Sent from Chrome Extension (Background Worker) to Native Host.

```json
{
  "version": "0.1.0",
  "type": "ask_mind",
  "requestId": "uuid-v4-string",
  "timestamp": "ISO-8601 UTC string",
  "tab": {
    "url": "string",
    "title": "string"
  },
  "slice": "string from page DOM, untrusted, may contain special chars"
}
```

| Field | Type | Required | Validation Rules | Description |
|---|---|---|---|---|
| version | string | Yes | Must equal "0.1.0". | Protocol version identifier. |
| type | string | Yes | Must equal "ask_mind". | Action type requested. |
| requestId | string | Yes | Non-empty UUID v4. Must be unique per request. | Correlation ID for message tracking. |
| timestamp | string | Yes | Valid ISO-8601 UTC timestamp string. Must be within 300 seconds (5 mins) of host system clock. | Freshness verification to prevent replay. |
| tab | object | Yes | Must contain url (string) and title (string). url must start with `https://gemini.google.com/`. | Metadata regarding origin tab. |
| slice | string | Yes | Text content extracted from Gemini DOM. Untrusted data. | Prompt/response context extracted from web page. |

### 1.2 Reply Envelope (`ask_mind_reply`)

Sent from Native Host to Chrome Extension.

```json
{
  "version": "0.1.0",
  "type": "ask_mind_reply",
  "requestId": "same uuid as the request",
  "status": "ok",
  "draft": "plain-text reply, only present when status=ok",
  "error": {
    "code": "string",
    "message": "string"
  },
  "timestamp": "ISO-8601 UTC string"
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| version | string | Yes | Protocol version identifier ("0.1.0"). |
| type | string | Yes | Message type identifier ("ask_mind_reply"). |
| requestId | string | Yes | Matches requestId from the incoming request (or null if unparseable). |
| status | string | Yes | Outcome status: "ok" or "error". |
| draft | string | Conditional | Plain-text draft response generated by Mind. Required if status is "ok". Omitted on error. |
| error | object | Conditional | Error details (code and message). Required if status is "error". Omitted on success. |
| timestamp | string | Yes | ISO-8601 UTC timestamp generated when reply was constructed. |

## 2. Hardening and Security Controls

The implementation strictly satisfies the five required threat-model controls:

**Control 1: Native Messaging Trust Boundary**
- File system permissions: The host Python script is installed with `chmod 700` and the host manifest with `chmod 600`.
- Pre-allocation payload limit: Before reading message content, the host reads the initial 4-byte little-endian header. If the declared length exceeds 1 MB (1,048,576 bytes), the process aborts reading immediately and returns an `OVERSIZED_PAYLOAD` error without allocating memory for the body.
- Strict validation: Requests are parsed and validated against schema, required fields, URL origin, timestamp freshness window (5 minutes), and request ID uniqueness (duplicate suppression).

**Control 2: Prompt Injection / XSS Prevention**
- All strings inside incoming requests (especially `slice`) are treated as untrusted data.
- Tag breakout sanitisation: Any literal occurrence of `<gemini_untrusted_output>` or `</gemini_untrusted_output>` inside the extracted slice is stripped prior to processing. Stripped events are logged to stderr.

**Control 3: Insert Draft Framework State (Step 2 Interface Rule)**
- Gemini's prompt input uses Angular/Wiz custom components. Setting `element.value` or `textContent` alone does not update internal component state.
- Extension-side code inserting drafts into Gemini's input must dispatch native DOM events immediately after setting input text:
  ```javascript
  inputElement.dispatchEvent(new Event('input', { bubbles: true }));
  inputElement.dispatchEvent(new Event('change', { bubbles: true }));
  ```

**Control 4: Completion Detection Strategy (Step 2 Interface Rule)**
- Extractor logic must observe the action-button transition inside Gemini's prompt container (transitioning from "Stop" generation" back to "Send").
- Extraction must require a 1,200 ms idle debounce on the active response DOM node to ensure streaming text and layout rendering are fully completed.

## Control 5: Native Host Runtime Environment**
- Runtime: macOS native `/usr/bin/python3`. Standard library dependencies only (`struct`, `json`, `uuid`, `datetime`, `re`, `sys`, `os`, `signal`). Zero external packages or pip dependencies.
- Stream framing: 4-byte little-endian length prefix read from `sys.stdin.buffer` and written to `sys.stdout.buffer`.

## 3. Protocol Error Codes

| Error Code | Description |
|---||---|
| `INVALID_JSON` | Payload is malformed or cannot be parsed as JSON. |
| `OVERSIZED_PAYLOAD` | Declared message byte length exceeds 1 MB limit. |
| `DUPLICATE_REQUEST_ID` | `requestId` has already been processed by this host session. |
| `STALE_TIMESTAMP` | Message timestamp is older or newer than the allowed 5-minute window. |
| `UNKNOWN_TYPE` | Message type field is not supported (only `ask_mind` is valid). |
| `WRONG_ORIGIN` | Tab URL does not originate from `https://gemini.google.com/`. |
| `MISSING_FIELD` | Mandatory schema field is missing or null. |
| `INVALID_FIELD` | Field fails type or format constraints (e.g. invalid version or timestamp format). |
| `INTERNAL_ERROR` | Uncaught host runtime error. |
